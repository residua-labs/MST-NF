## Read-off (the answer to the question)

1. **Nothing retrieves from the original vocabulary.** exact?/apply? cannot see through
   the CRT defs (opaque to unification); Loogle name searches hit unrelated Lean
   internals; LeanSearch's semantic search returns CategoryTheory noise. 0/7 probes.
2. **The abstraction step is the entire cost.** After replacing
   profile→`f`, sem→`g` (with the State×State pairing my §5 PairSem does),
   LeanSearch finds the needle at rank 1-2 in ~0.3s — even keyword-free
   (the semantic engine generalizes the phrasing). Loogle also works but needs
   either the name (`"factorsThrough"`: def 1 / iff 6) or Mathlib's own folded
   shape for exact?.
3. **exact? has a definitional blind spot**: the UNFOLDED iff misses while the
   one-direction (hypothesis-position) and folded forms hit — the def must sit
   where unification elaborates it, i.e. the user must state the goal in (or
   argument-wise into) Mathlib's vocabulary.
4. **The pairing gap is real**: the FDT's two-argument fiber shape
   (`?f ?a = ?f ?b → (?g ?a ?c ↔ ?g ?b ?c)`) has NO Loogle hit (200 entries, none
   FactorsThrough) — one must first see that State×State pairing turns it into
   Mathlib's one-argument form. That recognition is not provided by any tool
   measured; it is the agent's contribution.
5. **Tool availability notes**: loogle.net DNS-dead from the probe box; the
   official mirror loogle.lean-lang.org serves the UI but its JSON `/api` 404s
   (measurement done on the server-rendered HTML). Moogle's backend is gone
   (expired cert + Vercel DEPLOYMENT_NOT_FOUND). LeanSearch (leansearch.net,
   POST /search {"query":[...],"num_results":N}) was the only semantic engine up.
